# BUILD_GUIDE.md — Master Implementation Plan
**Project:** Temporal Web-Search Chat Agent  
**Stack:** Node.js + TypeScript, Express (SSE), SQLite (`better-sqlite3` WAL + FTS5 `trigram` + Entity Graph), `chrono-node`, Gemini 2.5 Flash (`thinkingBudget: 0`) / Claude Sonnet, Exa API (`web_search`), React + Vite + Tailwind CSS v4 + GSAP.

---

## 0. What Is Required Before Starting

### A. System & Runtime Requirements
* **Node.js:** `v20.11+` or `v22+` / `v24+`
* **Package Manager:** `npm` (strictly required by challenge rules: `npm install`, then `npm run dev`)
* **Zero External Services:** No Docker, Redis, or cloud databases required. SQLite initializes locally in `./data/agent.db` automatically on `npm run dev`.

### B. Required API Keys (List in `.env.example` and put values in `.env`)
```env
# 1. Primary LLM Key (Used for main agent synthesis & async fact extraction)
GEMINI_API_KEY="your_gemini_api_key_here"
# Optional fallback: ANTHROPIC_API_KEY="your_anthropic_api_key_here"

# 2. Single External Tool Key: Web Search (Exa or Tavily)
EXA_API_KEY="your_exa_api_key_here"
# Optional fallback: TAVILY_API_KEY="your_tavily_api_key_here"

# 3. Server Configuration
PORT=3000
VITE_PORT=5173
```

## 1. System Architecture & Core Flow

```text
+-----------------------------------------------------------------------------------+
|                                  CLIENT (Web UI)                                  |
|         - Real-time SSE Token Streaming & Tool Call Badges                        |
|         - Interactive Temporal Memory Graph & Fact Timeline (GSAP)                |
|         - Quick Seed Benchmark Scenarios for Evaluation                           |
+-----------------------------------------+-----------------------------------------+
                                          |
                                          v  POST /api/chat { message, sessionId }
+-----------------------------------------------------------------------------------+
|                            ORCHESTRATION LAYER (Node.js / TS)                     |
|                                                                                   |
|  1. Temporal Intent & Entity Router (`src/services/temporalRouter.ts`)            |
|     - Uses `chrono-node` for absolute date calculation against anchor `NOW()`     |
|     - Fast LLM (Gemini Flash) classifies intent: temporal delta vs direct fact    |
|     - Emits ISO date range [startDate, endDate] & keyword entities                |
|                                         |                                         |
|                                         v                                         |
|  2. Local Memory Engine (`src/db/index.ts`)                                       |
|     - Queries SQLite FTS5 (trigram) + date range filter over past turns           |
|     - Retrieves matching historical claims and entity facts                       |
|     - Injects `<past_conversation_context>` into reasoning prompt                 |
|                                         |                                         |
|                                         v                                         |
|  3. Primary Reasoning Agent (`src/services/agent.ts`)                             |
|     - Enforces STRICT single-tool constraint: `web_search(queries[], start_date)` |
|     - Executes batched parallel search queries via Exa / Tavily                   |
|     - Performs delta comparison (Past Claim vs Current Web Truth)                 |
|     - Streams SSE events (`token`, `tool_call`, `temporal_delta`, `done`)         |
+-----------------------------------------+-----------------------------------------+
                                          |
                                          v  Post-turn hook (async, non-blocking)
+-----------------------------------------------------------------------------------+
|                         BACKGROUND FACT EXTRACTOR (Async)                         |
|     - Parses completed assistant answer into structured entity facts              |
|     - Records { topic, entities, claims, timestamp } into `memory_facts` table    |
+-----------------------------------------------------------------------------------+
```

## 2. Database Schema (`./data/agent.db`)

SQLite database initialized in WAL mode for high-concurrency read/writes:

### A. Tables
1. **`sessions`**:
   - `id` (TEXT PRIMARY KEY)
   - `title` (TEXT)
   - `created_at` (TEXT ISO)
   - `updated_at` (TEXT ISO)

2. **`messages`**:
   - `id` (TEXT PRIMARY KEY)
   - `session_id` (TEXT REFERENCES sessions(id))
   - `role` (TEXT CHECK(role IN ('user', 'assistant', 'system')))
   - `content` (TEXT)
   - `tool_calls` (TEXT JSON)
   - `temporal_meta` (TEXT JSON)
   - `created_at` (TEXT ISO)

3. **`memory_facts`**:
   - `id` (TEXT PRIMARY KEY)
   - `session_id` (TEXT REFERENCES sessions(id))
   - `recorded_date` (TEXT ISO YYYY-MM-DD)
   - `topic` (TEXT)
   - `entities` (TEXT JSON: `["HubSpot", "Salesforce", "Pipedrive"]`)
   - `claim_summary` (TEXT)
   - `raw_evidence` (TEXT)
   - `created_at` (TEXT ISO)

4. **`fts_messages`** (FTS5 Virtual Table):
   - `content`, `tokenize='trigram'`
   - Synced via SQLite triggers on INSERT into `messages`

5. **`fts_facts`** (FTS5 Virtual Table):
   - `topic`, `claim_summary`, `entities`, `tokenize='trigram'`
   - Synced via SQLite triggers on INSERT into `memory_facts`

---

## 3. Strict Single-Tool Specification

The agent strictly implements **ONLY ONE TOOL**:
```typescript
interface WebSearchToolInput {
  queries: string[];               // Batched parallel search queries
  start_published_date?: string;   // Optional ISO date filter (e.g. for changes since past date)
}
```
* **No python executor tool**
* **No shell tool**
* **No browser automation tool**
* Only `web_search` against Exa / Tavily API.

- [x] Seed fixture data helper for instant hackathon verification (pre-loaded Oct/Nov 2024 discussions).

### Phase 3: Temporal Intent Router & Web Search Tool
- [x] Implement `Backend/src/services/temporalRouter.ts` using `chrono-node` for relative date expressions ("last month", "on 3rd Nov", "2 weeks ago") + Gemini Flash intent extraction.
- [x] Implement `Backend/src/services/searchTool.ts` wrapping Exa API with Tavily fallback and mock/live resilient modes.

### Phase 4: Core Agent & SSE Streaming
- [x] Implement `Backend/src/services/agent.ts`:
  - Temporal Memory Pre-Pass: retrieves matching past facts & messages.
  - System prompt framing past facts vs current verification requirement.
  - LLM tool-calling loop using `web_search`.
  - SSE token streaming: `token`, `status`, `tool_call`, `tool_result`, `delta_detected`, `done`.
- [x] Implement `Backend/src/services/factExtractor.ts`: background async extractor storing new facts into SQLite without blocking SSE completion.
- [x] Implement Express routes in `Backend/src/server.ts`:
  - `POST /api/chat` (SSE stream)
  - `GET /api/sessions` & `GET /api/sessions/:id/messages`
  - `GET /api/facts`
  - `POST /api/seed` (pre-populates demo scenarios)

### Phase 5: Modern UI (Frontend)
- [x] Install & configure Tailwind CSS v4, Lucide React icons, and GSAP.
- [x] Implement Temporal Memory Drawer: visual fact timeline with interactive date stamps and entity tags.
- [x] Implement Live Agent Chat:
  - Real-time SSE token rendering with markdown formatting.
  - Visual Tool Call Collapsible Card showing live search queries and sources.
  - Temporal Delta Alert Badge highlighting what changed between past and present.
- [x] Demo Preset Scenarios bar: 1-click test cases for temporal queries.

### Phase 6: End-to-End Verification
- [x] Verify `npm install` and `npm run dev` from root runs cleanly.
- [x] Test temporal query: Seed past claim -> ask for update -> verify tool calls and delta output.
